## 2. Where the workspace lives

- **Single source:** `localStorage["authsec_session_v2"]` (`utils/sessionManager.ts:23,37`). It holds `token`, `jwtPayload` (decoded client-side), and separate fields `workspace_id`, `project_id`, `client_id`, `user_id`, `roles` and `scopes`, with `expiresAt = now+30d` (`authSlice.ts:161`).
- `session.workspace_id` is **not** taken from the token. It is set from the `workspaceId` that comes back with the login step-1 response / Redux login data (`authSlice.ts:96,150`; `AdminAuthContext.tsx:636-640, 688-707`). That value can be seeded from URL params `?workspace_id=&email=` or from an unsigned base64 `?handoff=` payload (`AdminWebAuthnRouter.tsx:37-49, 53-79`; `utils/handoff.ts:16-42`).
- `getWorkspaceId()` (`utils/workspace.ts:8-24`) tries `session.workspace_id`, then `jwtPayload.workspace_id`, then a **UUID-shaped subdomain from the URL**. All three are user-editable local state rather than the verified claim. `jwt.ts:56` also falls back to the legacy `tenant_id` claim.
- **Sent to the backend:**
  - Body: `withSessionData()` (`baseApi.ts:62-70`) adds `workspace_id`, `client_id` and `project_id` from localStorage to bodies in 18 API files (roles, permissions, resources, users, invites, sync-configs, domains, dashboard, workloads, bindings, and others).
  - Path: `/authsec/uflow/v2/tenants/:ws/...` (`membershipApi.ts:122-258`), `/authsec/uflow/admin/tenants/:ws/domains` (`domainApi.ts:73-164`), `/authsec/uflow/user/enduser/:ws/:uid`, `/authsec/v1/workspaces/:ws/...` (`iamAggregatesApi.ts:140`), `/authsec/hmgr/saml/metadata/:ws`.
  - Query: `?workspace_id=` in `logsApi.ts:344,395,424,448`.
  - Header: no `X-Tenant` or `X-Workspace` header is sent anywhere. (The backend's `middlewares/security.go:105` only logs `X-Workspace-ID`.)
- **Backend acceptance:**
  - Path `:workspace_id` is checked against the token by `ValidateWorkspaceFromToken` (`middlewares/workspace_validation.go:11-49`) on the uflow admin, v2, user and logs groups. Safe.
  - Body `workspace_id` is **not** validated by that middleware. Confirmed trusting handlers: `POST /authsec/uflow/admin/groups` (`controllers/admin/groups_controller.go:56-96`, which writes `config.DB` with `req.WorkspaceID`); `groups/map`, `DELETE groups/map` and `groups` update (`groups_controller.go:137-190,545`); and `sync-configs/create|update|list|delete` (`controllers/admin/sync_config_controller.go:55,173,237,372`). An admin of workspace A can create groups or sync configs, including encrypted AD/Entra credentials, in workspace B by changing the body. That is a **cross-workspace write (P0, backend)**. The UI keeps the pattern alive by sending body `workspace_id`.

## 3. Switching and logout hygiene

- **Workspace switching:** none exists. `switchProject` is a stub that shows an error toast (`AuthContext.tsx:240-249`). The only workspace choice is at login (`TenantDomainSelectionModal` in `AdminOIDCCallbackPage.tsx:8`).
- **Logout** (`nav-user.tsx:54` → `AuthContext.signOut` :213-224 → `authSlice.logout` :69-78 → `SessionManager.clearSession` `sessionManager.ts:96-144`):
  - Cleared: `baseApi` cache via the listener (`store.ts:57-65`), IGA graph revisions, `auth` slice, localStorage `authsec_session_v2`, `jwt_token`, `auth_token`, `access_token`, `refresh_token`, `authsec-ui-theme` (an odd one to clear), oauth_* in sessionStorage, and every non-HttpOnly cookie.
  - **Not cleared:**
    - RTK caches of the separate `userAuthApi`, `oidcApi` and `deviceApi` (`store.ts:73-75`). `deviceApi` caches TOTP/CIBA device lists.
    - Redux `adminWebAuthn` (including `authToken`, email and workspaceId; `adminWebAuthnSlice.ts:44,116`) and `oidcWebAuthn`. `resetAdminWebAuthnState` exists but is not called on logout.
    - sessionStorage `authsec_verification_v2`: written to sessionStorage (`authSlice.ts:230`) but removed from **localStorage** (`sessionManager.ts:100`).
    - sessionStorage `admin_oauth_email`, `admin_oauth_tenant`, `uflow_*`, `saml_*` (`OIDCCallbackPage.tsx`, `OIDCLoginPage.tsx:380`).
    - No full page reload, so all of the above live until the tab closes.
  - **Unscoped localStorage that survives users** (low sensitivity): `authsec_wizards` (`wizardStorage.ts:3`), `authsec_guided_tours` (`tourStorage.ts:6`), `activationCard_dismissed` (`ActivationSection.tsx:17`), `scim_connections_info_dismissed_v1` (`ScimConnectionsPage.tsx:38`), `oidcProviderTableColumns`, the density pref, and the graph `EDGE_LABELS_KEY`. These are scoped correctly per `workspace_id:user_id`: column prefs (`use-column-preferences.ts:13`), discovery provider pref (`iga/discovery/sources.ts:64`), AWS quick-create (`AWSQuickCreateFlow.tsx:57`) and graph saved layout.
- **Cross-tab / shared-browser gap (P1):** the `storage` listener (`AuthContext.tsx:75-83`) runs `checkSession`, which re-hydrates Redux **only when `!state.isAuthenticated`** (`authSlice.ts:184`). If tab 2 signs in as a different user or workspace, tab 1 keeps the old `jwtPayload`, so `sessionIdentity()` does not change and **`resetApiState` never fires**. Meanwhile `baseApi` starts sending the new token, read from localStorage per request. Tab 1 keeps showing workspace A's cached data, and any mutation it issues runs with workspace B's token and B's IDs mixed with A's cached IDs.

## 4. Tokens

- Stored in **localStorage**: `authsec_session_v2.token`, plus a duplicate `jwt_token` (`AdminAuthContext.tsx:172,684`). It is readable by any XSS, and there is no CSP (server.js and index.html set none). `credentials: "include"` is set as well.
- No refresh flow, no 401 interceptor and no forced logout. The session only expires through `checkSession` every 5 minutes or on tab focus (`AuthContext.tsx:87-110`), using JWT `exp` decoded client-side (`sessionManager.ts` `isSessionValid`).
- Client-side decode is used for identity and display only. `ProtectedRoute` checks only `isAuthenticated` (`ProtectedRoute.tsx:27`). `SessionManager.hasRole/hasScope` exist but have no callers. Admin vs. end-user audience comes from the URL context (`useRbacAudience`) and is not a security boundary, because the backend enforces it. **No client-side authorization decision was found.**
- Tokens are logged: `OIDCCallbackPage.tsx:612` logs the exchanged tokens (`console.log("Token exchange successful:", normalizedTokens)`), and `auth/webauthn/WebAuthnPage.tsx:20` logs `localStorage.jwt_token`.
- Token minting contract (**P0, backend**): the admin UI gets its JWT from `POST /authsec/uflow/login/webauthn-callback` with body `{email, mfa_verified: true, workspace_id, flow_context}` (`AdminAuthContext.tsx:156-165`; `webauthnApi.ts:311`). The handler (`controllers/admin/workspace_admin_controller.go:743-790`, route `routes.go:2000`) is **unauthenticated**. It looks up the workspace by the body `workspace_id`, trusts `mfa_verified`, and issues an **admin** JWT for the workspace owner's email. I found no check in the handler that the WebAuthn ceremony actually happened. The end-user equivalent (`/authsec/uflow/auth/enduser/webauthn-callback`, `enduser_auth_controller.go`) also gates only on `MFAVerified`. **Verify** that no other layer binds this; I saw none in the routes or in `cmd/main.go` global middleware.

## 8. Recommendations (ordered)

1. Backend: make `webauthn-callback` (admin and end-user) require a server-side proof of the completed ceremony, such as a one-time ticket from `finishAuthentication`. Ignore body `workspace_id` everywhere, or reject it when it differs from the token: groups, sync-configs, and others.
2. UI: delete `withSessionData`'s `workspace_id`, `client_id` and `project_id` injection. Derive the workspace only from the verified token claim, and drop the `session.workspace_id` field and the URL-subdomain fallback in `getWorkspaceId`.
3. Logout and identity change: reset `userAuthApi`, `oidcApi` and `deviceApi` plus the webauthn slices, clear sessionStorage auth keys, and preferably do a hard reload. Fix the cross-tab rehydrate so it compares the token rather than `isAuthenticated`.
4. Add a global 401 handler in `baseQuery` that logs out, and add a CSP. Remove the token `console.log`s. Stop exposing and logging `VITE_HUBSPOT_ACCESS_TOKEN` in `server.js:21,30,86`.
5. Fix the P2 path mismatches in section 5. Delete the dead API modules. Make `audit-api-routes.sh` fail closed and regenerate it from the backend route table, for example with this audit's extractor.
