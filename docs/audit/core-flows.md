### Service chain
1. `pending_registrations` + `otp_entries` → SMTP OTP email (fire-and-forget).
2. On completion, one transaction inserts `workspaces`, `workspace_domains` (auto-verified when the domain is under `TENANT_DOMAIN_SUFFIX`), `users`, the admin role through `AdminSeedRepository.EnsureAdminRoleAndPermissionsTx`, `role_bindings` and `workspace_memberships`.
3. After commit, a goroutine calls Vault `SaveSecretToVault`.

Columns were checked against `migrations/master/001_bootstrap.sql` (workspaces, pending_registrations, workspace_memberships, role_bindings, users). They match.

**External dependencies:** SMTP (optional: failures are only logged) and Vault (best-effort). No Hydra.

### Status: PARTIAL

**Is the single-tenant 409 guard still there? Yes, and it is now unconditional.**
- `admin_auth_controller.go:523-535`: the handler counts active non-system workspaces and returns `409 "Single-tenant deployment: only one admin is allowed."` when any exist.
- When commit 764a654 added it, it was gated on `config.MTPluginClient == nil || !IsAvailable()`.
- Commit e9ccb83 deleted the mt-plugin client (`internal/mtplugin` is gone, and nothing reads `MT_PLUGIN_GRPC_ADDR`; it appears only in hint strings at `admin_user_controller.go:1013` and `migration_controller.go:69`). The guard now **always** fires once one workspace exists.
- **P1** for multi-tenancy.

**The guard is inconsistent: other paths create a second workspace freely.**
- **Bootstrap path:** `AdminBootstrap` (`:1226-1371`) has no guard, and `AdminCompleteRegistration` (`:852`) has none either. The README documents bootstrap as the sign-up path (`README.md:298`). In practice a second workspace **can** be created; only `/register` refuses.
- **OIDC/social path:** `handleRegistrationCallback` and `CompleteRegistration` (`oidc_controller.go:927, 1207`) have no guard.
- **`POST /uflow/admin/tenants` (CreateTenant):**
  - Any workspace owner/admin can create a bare `workspaces` row (`database/workspace_repository.go:73`).
  - It creates no admin user, no membership, no roles and no slug. `provider` is inserted as `''`, and `workspace_domain` is neither suffix-normalised nor uniqueness-checked.
  - The orphan workspace is `active`, so it then **trips the `/register` guard**.
  - **P2.**
