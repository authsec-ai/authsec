Concrete cross-tenant attack paths:
1. **SPIFFE impersonation (finding 1).**
   1. Admin of A: `POST /authsec/workload-identity-providers {kind:"spiffe", issuer:"https://evil", jwks_uri:"https://evil/jwks"}`.
   2. Mint an RS256 SVID with `sub=<B SA spiffe_id>` and `aud=<issuer>/oauth/token`.
   3. Call `POST /oauth/token grant_type=client_credentials client_assertion_type=urn:authsec:…:spiffe-svid`. This returns a native M2M token for B's SA on B's RS (requires `XAA_M2M`).
2. **XAA impersonation (finding 2).**
   1. Admin of A: `POST /authsec/trusted-issuers {iss:"https://evil", provider_name:"<B's provider name>" or "authsec:id-jag", jit_provisioning:true}`.
   2. Register an agent client by DCR and get it approved once for B's RS (an innocuous access request).
   3. Forge an ID-JAG with `sub` set to a victim B user's federated subject or UUID. Redemption mints an XAA token *as that user* with their RBAC scopes.
   4. Separately, `DELETE /authsec/trusted-issuers/<B's issuer id>` revokes B's federation and its live tokens.
3. **CIBA push phishing (finding 3).** With no account: `POST /authsec/uflow/auth/ciba/initiate {login_hint:"admin@victim", binding_message:"Approve AuthSec sign-in", scopes:[…]}`, then poll `/ciba/token`. Result: a 365-day session JWT accepted by every `AuthMiddleware` route, with `RequireWorkspaceRole` satisfied by the victim's DB membership.

## 3. Revocation

- **Native tokens:** `revoked_tokens(iss, kind, jti)` is the source of truth (`internal/tokens/store.go:27-62`) and is checked by `VerifyProtectedResourceToken` (`:87`) and by the token-exchange subject check (`oauth_as_controller.go:1671`).
  - Writers:
    - `/oauth/revoke` (`:3090-3119`): possession-based, no client auth (P3).
    - Admin `DELETE /authsec/tokens/:jti`: **workspace-scoped** (`services/oauth_as_service.go:2742-2780`, checks `nt.WorkspaceID`). An M2M token's workspace is the SA's, so an RS owner in another workspace cannot revoke it (P2).
    - Governance expiry (`repository/governance_repository.go:337-378`): by `subject_id` with no workspace filter. UUIDs make collisions negligible (P3).
    - Trusted-issuer revoke: cross-tenant (finding 2).
  - The table has no `workspace_id`, so scoping is enforced only at the endpoints.
- **Hydra tokens:** proxied `/oauth2/revoke`, plus registration-status and live-RBAC checks at introspection.
- **HMAC session JWTs: no revocation.**
  - `middlewares/token_blacklist.go:18` has **no callers** (re-verified).
  - `TokenService.BlacklistAccessToken` uses Redis, which is not connected; the controller is "not mounted" (`controllers/platform/token_controller.go:147`). It also passes `15*60` as a `time.Duration`, which is 900 ns (`:162`), so even when wired the entry would expire at once (P3).
  - The only mitigation is that `RequireWorkspaceRole` re-reads membership from the DB.
- **Delegation JWT-SVIDs:** status flag only, never enforced (finding 10).
- **ID-JAGs:** replay cache only. Nothing reads `revoked_tokens kind='id_jag'` (P3).
- **SPIRE OIDC tokens:** `SpireOIDCToken.revoked` is checked only for JWT-SVIDs, not for access tokens (`spire_controller.go:1597-1611`, P2).

## 4. Side channels (from the delegated side-channel audit, cross-checked where noted)

- **Caches:**
  - All are per-process (Redis is not connected).
  - Tenant-scoped or safe: GitHub installation tokens (keyed by workspace and app), XAA issuer JWKS (keyed by globally-unique iss), SPIFFE JWKS (keyed by workspace, but the key comes from an unverified claim and is unescaped, finding 19), JWT-SVID private keys (keyed by workspace, no TTL, so rotation is invisible until restart, P3), IGA membership, external-service controller.
  - Dead or unsafe-if-used: Hydra JWKS kid-only cache, `DecodeJWTToken` (no callers), Redis `auth:token:<raw bearer>` key (`monitoring/cache.go:241`, unused).
  - The WebAuthn session store is unbounded, and admin keys omit the workspace (`buildChallengeKey(op,email,"admin")`); with email unique only per workspace, two tenants' admins collide (P1, uncertain).
- **Background jobs:**
  - Tenant-scoped with leases and fencing: AWS scan, GitHub discovery, projection.
  - GCP scan is a bare goroutine with only a process-local lock (P2).
  - SoD, JML, policy, expiry workers and the Hydra reconciler have no cross-replica lease, so work is duplicated (P3).
  - The PKI retry worker updates a non-existent `workspaces.workspace_id` column and always fails (`services/pki_retry_worker.go:83`, P2).
  - The native key reloader can overwrite keys on a Vault blip (finding 17).
- **Webhooks:**
  - Inbound GitHub: HMAC with a **single deployment-wide secret**. The installation-to-workspace binding comes from the unsigned `X-GitHub-Installation-ID` header and `action` from an unsigned query parameter, so a replayed signed body can trigger cross-workspace rescans (P2).
  - Outbound policy-warning webhook: optional per-workspace HMAC secret stored **plaintext**; only an `https://` check (SSRF, P2).
- **File storage:** none.
- **Logging:** tokens, OTPs, state and PKCE keys in plaintext (finding 14). Most log lines carry no trustworthy `workspace_id`; the security logger takes it from the client header `X-Workspace-ID`. `internal/authz/authz.go` logs every authz decision verbosely, which adds volume but no secrets.
- **Audit:**
  - `workspace_id` is NOT NULL in `agent_action_audit_log`, `authorization_decision_logs`, `scim_events`, `auth_issuance_audit` and `connector_action_audit`.
  - It is nullable text in `audit_events` and `spire_audit_logs`.
  - The tables are not append-only: no triggers or REVOKE, and the app deletes rows after 90 days (`monitoring/audit.go:225-227`).
  - Writes are fire-and-forget or stdout-only on failure (`monitoring/audit.go:61-70`, `internal/policy/simple_pdp.go:177-189`).
  - `authorization_decision_logs` appears to have no writer (uncertain).
  - `middlewares.Audit` only prints to stdout (`middlewares/logging_middleware.go:228`), so audit for `DelegateToken` and legacy CIBA initiate is not persisted (P2).
- **Metrics:** `/authsec/metrics` is unauthenticated (process metrics only). The `workspace_id` label comes from an untrusted header but the middleware is not registered (P3).

## 6. Suggested fix order

1. Filter the `kind=spiffe` service-account lookup by `providerWS`, and require a trust domain on spiffe providers (finding 1).
2. Make `trusted_issuers` workspace-owned (or platform-admin-only). Scope `MapSubject` provider names to the issuer row (for example `provider_name = 'xaa:' || issuer.id`). Forbid the reserved `authsec:id-jag` (finding 2).
3. Remove or gate legacy `/auth/ciba/*`. Require `AuthenticateClient` on workspace CIBA and token exchange. Resolve CIBA scopes through `ScopeResolver` (findings 3, 5, 7, 8).
4. Require an authenticated session plus step-up for WebAuthn `beginRegistration` when the user already has credentials, and delete the attestation fallback (finding 4).
5. Enforce brokering deny and PDP deny regardless of `POLICY_ENGINE_MODE`, or default it to `enforce` (finding 6).
6. Gate `/uflow/sdk/delegation-token` by admin role or agent identity, stop storing the token, and add revocation checks to SVID verification (findings 9, 10).
7. For HMAC sessions: require `exp`, `jti` and `token_type` per route class; add a DB revocation table; split secrets per token class; remove chained `/auth/token/generate` re-minting (findings 11, 12).
8. Read `TOTP_ENCRYPTION_KEY` correctly and fail closed (re-encryption migration needed). Scrub secrets from logs. Use the SSRF-safe client in `fetchURL`.
