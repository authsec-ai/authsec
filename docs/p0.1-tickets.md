# P0.1 — Implementation tickets

**Parent spec:** [`p0-observability-spec.md`](./p0-observability-spec.md) (v4.2.1) · **contract:** [`p0-schema-and-api.md`](./p0-schema-and-api.md) (v4.2.1). **Step 1 locked.**
**Goal of P0.1:** the canonical event contract + correlation IDs + native/broker/admin capture + events read API. **No SDK changes** (that's P0.2) — P0.1 is populated entirely by existing server-side traffic and dogfooded on mcpauthz.
**Capture points in P0.1:** token issuance (native, in-tx) + ID-JAG (in-tx) + revocation + admin + **authz.allowed/denied (evalPDP)** + **token.validation_denied (broker verify)** + broker tool lifecycle. (Hydra issuance + SDK ingest + introspection-side validation_denied are P0.2.)

**Conventions (per repo):** single-state bootstrap schema (edit `CREATE TABLE` inline in `migrations/master/001_bootstrap.sql`, then wipe + re-bootstrap — never `ALTER`); controllers in `controllers/platform/`, services with `db *gorm.DB` from `config.DB`; routes via a `register*Routes(r gin.IRouter)` helper under `/authsec`; verify with `go build ./...` + `go vet` + manual smoke (no unprompted tests).

Ordering: **T1 → T2 → {T3, T4, T5, T5b} → T6 → T7.**

## T1 — Schema: `agent_activity_events`
**Depends:** none · **Files:** `migrations/master/001_bootstrap.sql` · **Requires wipe + re-bootstrap.**

Add the table + indexes from spec §3.1 (v4.2.1 — includes `token_kind`, `token_expires_at`, and the generated `token_key`), appended in the tail migration section following the bootstrap convention. Normal indexed table — **no partitioning** in P0.

- `occurred_at` = producer clock; `received_at DEFAULT now()` (retention + alert time-gating key on `received_at`).
- `token_key text GENERATED ALWAYS AS (COALESCE(token_jti, token_ref)) STORED`.
- Idempotency: `UNIQUE (workspace_id, reporter_id, source_event_id, event_type)`.
- Indexes: `(ws, occurred_at DESC)`, `(ws, oauth_client_id, occurred_at DESC)`, `(ws, application_id, occurred_at DESC)`, `(ws, event_type, occurred_at DESC)`, `(ws, tool_call_id)`, `(token_jti)`, `(ws, token_key)`.

**Acceptance:** fresh bootstrap creates the table + all indexes; the `token_key` generated column resolves; boot log clean; `go build ./...` green.

## T2 — `activity` package: `Record()` + event model + two write modes
**Depends:** T1 · **Files:** new `models/agent_activity_event.go`, new `internal/activity/record.go` (or `services/activity/`).

GORM model `AgentActivityEvent` (`TableName() → "agent_activity_events"`), and the central recorder. Two entry points so callers pick the write mode explicitly (spec §4/§6):

```go
// Event is the caller-filled payload; Record stamps event_id, received_at, defaults.
type Event struct {
    WorkspaceID   uuid.UUID
    Producer      string // "as" | "broker" | "admin" | "sdk-*"
    ReporterID    string // server: = Producer; SDK: rs_id
    SourceEventID string // derived from the AUTHORITATIVE id (see below), not a fresh random
    Category, EventType string
    Outcome       string
    ToolCallID, MCPRequestID, OperationID, RequestID, SessionID string
    TokenJTI, TokenRef, TokenKind string   // token_kind: access_token | id_jag
    TokenEngine, TokenFamily, GrantType, SourceGrantJTI string
    TokenExpiresAt *time.Time
    OAuthClientID, ActorClientID, ActorSpiffeID string
    SubjectType   string
    SubjectID     *uuid.UUID
    OwnerEmail, OwnerTeam string
    ApplicationID, ConnectorID *uuid.UUID
    ToolName      string
    ScopesRequested, ScopesGranted []string
    Transport     string
    HTTPStatus, JSONRPCErrorCode *int
    MCPIsError    *bool
    LatencyMs     *int
    ErrorCategory, Reason string
    OccurredAt    time.Time
    Attributes    map[string]any // redacted metadata only
}

// RecordTx: for issuance — MUST run inside the caller's authoritative tx.
// If the insert fails, the caller's tx (token issuance) fails too.
func RecordTx(tx *gorm.DB, ev Event) error

// RecordBestEffort: single best-effort event (admin). Never blocks enforcement:
// runs under a SHORT context timeout (e.g. 250ms); on error/timeout increments
// activity_emit_failures_total{producer} and returns. (Bounded async queue is an
// allowed impl if the sync insert can't meet the latency budget — spec §NFR.)
func RecordBestEffort(ctx context.Context, ev Event)

// RecordBatchBestEffort: broker path. Writes the full tool lifecycle for one call
// in ONE insert (avoids partial lifecycles + 3 round-trips). Same timeout/metric rule.
func RecordBatchBestEffort(ctx context.Context, evs []Event)
```

- **`source_event_id` = the authoritative id, not a fresh UUID:** issuance/revocation events → the token `jti`; broker tool events → the pre-generated `connector_action_audit` row UUID; **attempt events (`token.validation_denied`, `authz.*`) → the request/attempt id, NOT the token jti** (a revoked token gets misused many times; keying on jti would collapse every attempt into one row and hide the pattern the alert needs). `event_type` keeps lifecycle steps of one id unique.
- Insert uses `ON CONFLICT (workspace_id, reporter_id, source_event_id, event_type) DO NOTHING`.
- Default `OccurredAt` to now if zero (server producers); validate required correlation fields for `tool.*`.

**Acceptance:** package compiles; `RecordTx` joins a passed tx; `RecordBestEffort`/`RecordBatchBestEffort` swallow errors + timeout + bump the metric and never delay the caller past the budget; duplicate `(ws,reporter,source,type)` is a no-op.

## T3 — Issuance emitters (transactional) + `GrantType` plumbing
**Depends:** T2 · **Files:** `internal/tokens/issuer.go` (`NativeClaims` :15, `Issue` ~:117, `IssueIDJAG` :80), `controllers/platform/oauth_as_controller.go` (client-creds :872, jwt-bearer/XAA :1245, token-exchange :1435), **`services/workspace_ciba_service.go:~435` (native CIBA issuance — NOT in oauth_as_controller)**.

- **Add `GrantType string` to `NativeClaims`** (it doesn't exist today, `issuer.go:15`) and set it at **every** call site: client_credentials (`oauth_as_controller.go:872`), jwt-bearer (`:1245`), **ciba (`workspace_ciba_service.go:~435`)**. (Token-exchange goes through `IssueIDJAG`, not `Issue`.)
- In `Issue`, **inside the same tx as the `native_tokens` insert**, `RecordTx` a `token.issued` with `token_kind='access_token'`, `grant_type`, `token_jti`, `token_family`, `token_expires_at`, `subject_*`, `oauth_client_id`, `actor_*`, `source_grant_jti` (XAA links to its ID-JAG), `application_id` (= aud/RS). The XAA companion **is not a separate `token.exchanged`** — the ID-JAG is emitted separately (below).
- **`IssueIDJAG` currently signs and returns with NO transaction** (`issuer.go:76`). Wrap it: **open a tx → `RecordTx` a `delegation.issued`** (`token_kind='id_jag'`, `grant_type='token-exchange'`, `token_jti`=the ID-JAG jti) **→ commit → only then return the signed ID-JAG.** **Never** `token.issued`; never counted as an access token.
- `source_event_id` = the token/ID-JAG `jti` (authoritative; keeps retries idempotent).

**Acceptance:** issuing M2M/XAA/CIBA tokens writes exactly one `token.issued` (access) row atomically; a token-exchange writes one `delegation.issued` (id_jag) row and **zero** `token.issued`; forcing the event insert to fail rolls back the token issuance (proves the guarantee); token metrics counting `DISTINCT token_key WHERE token_kind='access_token'` exclude ID-JAGs.

## T4 — Broker emitter (best-effort, after execution)
**Depends:** T2 · **Files:** `controllers/platform/connector_broker_controller.go` (`auditAction` ~:570–:640).

- **Add broker timing first:** `runAction` does **not** currently measure or populate `ConnectorActionAudit.LatencyMs` (the struct at :613 leaves it zero). Wrap the provider call to measure elapsed ms and set it on both the audit row and the events.
- Alongside the existing best-effort `connector_action_audit` insert (:611), call **`RecordBatchBestEffort`** with the resolved lifecycle in **one insert** (not three): `tool.requested` + (`tool.allowed`|`tool.denied`) + (`tool.completed`|`tool.failed`|`tool.not_executed`), all sharing one `tool_call_id` = the pre-generated `connector_action_audit` row UUID (also stored in `attributes.action_audit_id`).
- `source_event_id` = that connector-audit UUID; `event_type` distinguishes the steps → idempotent.
- Map `authz_outcome`→allowed/denied, `action_outcome`→completed/failed, `provider_status`→`http_status`, `latency_ms`, `deny_reason`→`reason`; identity from `authCtx` (subject/actor/owner/token_family/jti, `token_kind='access_token'`); `application_id`=broker RS; `connector_id`.
- **Must be ASYNC — not a synchronous best-effort insert.** `auditAction` runs **synchronously before `runAction` returns** (`connector_broker_controller.go:660`), so a 250 ms sync timeout would add up to 250 ms to the provider response. Push the lifecycle to a **bounded in-process channel** (drop + `activity_emit_failures_total{producer="broker"}` if full); a worker drains it. The request path enqueues and returns immediately — zero added latency, provider result never altered.

**Acceptance:** an allowed broker call yields requested+allowed+completed in one write with a real `latency_ms`; a denied one yields requested+denied; a stalled/full event pipeline adds **0 ms** to the provider response (measured) and bumps the metric.

## T5b — Authz + `token.validation_denied` emitters (best-effort)
**Depends:** T2 · **Files:** `controllers/platform/oauth_as_controller.go` (`evalPDP` :78); `services/protected_resource_verifier.go` (`VerifyProtectedResourceToken` ~:86) + its callers (broker here; introspection is P0.2/T10).

- **`authz.allowed` / `authz.denied`** at `evalPDP` (mint-time PDP) — previously unticketed.
- **Typed denial, emitted by the caller — not inside the verifier.** `VerifyProtectedResourceToken` is shared by broker auth **and** native introspection, so it must **return a typed denial** `{reason, token_jti?, subject, application}` rather than emit — otherwise P0.1 would silently start introspection capture and collide with T10. The **broker caller** emits `token.validation_denied` from that typed denial; T10 makes the introspection caller emit its own.
- **`reason`** must distinguish `suspended` from `rbac_revoked` (the current code collapses suspension into a generic RBAC failure). Service accounts have a *suspended status* but **no `suspended_at`** timestamp — so `access_after_suspension` gates on the corresponding **admin `identity_suspended` event's timestamp** (or a defined status-change timestamp), not a missing column.
- `source_event_id` = the request/attempt id (per T2), so repeated misuse of one revoked token yields distinct rows.

**Acceptance:** verifier returns a typed denial (no emit inside it); a mint-time deny writes `authz.denied`; a revoked token against the broker writes `token.validation_denied` reason=revoked, a suspended one reason=suspended (not rbac_revoked); repeated misuse of one revoked token yields N distinct rows; the security alerts fire off them (dry-run 4).

## T6 — Events read API (`GET /authsec/activity/events`)
**Depends:** T3–T5 (needs data) · **Files:** `routes/routes.go` (`registerActivityRoutes`), new `controllers/platform/activity_controller.go`, new `services/activity_service.go`.

Style-B route under the console 3-middleware stack (`AuthMiddleware + RequireWorkspaceRole("owner","admin") + ValidateWorkspaceFromToken`). Workspace from JWT via `extractWorkspaceID(c)`.

```
GET /authsec/activity/events
  ?from&to&event_type&category&outcome&client_id&application_id&tool_call_id
  &token_key&token_jti&reason&cursor&limit
```
- `token_key` filters native + Hydra; `token_jti` is native-only. `from/to` filter on `received_at`.
- **Cursor-based pagination** (opaque base64 of `occurred_at,event_id`), never offset; `limit` capped per §NFR.
- Service method `ListByWorkspace(workspaceID, filters, cursor, limit)`; all queries workspace-scoped.
- Response: `{ events: [...], next_cursor: "..." }` with the columns from §3.1.

**Acceptance:** returns only the caller's workspace; filters compose; `next_cursor` round-trips; another workspace's events never appear. `go build`/`go vet` clean; if a UI slice is added, `tsc --noEmit` clean.

## P0.1 exit criteria
Fresh bootstrap + a live mcpauthz run, with these **explicit, separate** smoke steps (an ordinary tool call does not by itself revoke a token, and only **connector-broker-mediated** calls are visible in P0.1 — SDK-managed MCP calls stay invisible until P0.2):
1. **Token issuance:** issuing an M2M token writes one `token.issued` (access); a token-exchange writes one `delegation.issued` (id_jag) and zero `token.issued`.
2. **Broker tool call:** a connector-broker tool call writes `tool.requested→allowed/denied→completed/failed` in one row-set sharing a `tool_call_id`, with real `latency_ms`.
3. **Revocation (separate step):** explicitly revoking that token writes one `token.revoked`; then reusing it against the broker writes one `token.validation_denied` (reason=revoked).
4. All rows workspace-scoped + idempotent; queryable via `GET /authsec/activity/events` by `tool_call_id`, `client_id`, time.
